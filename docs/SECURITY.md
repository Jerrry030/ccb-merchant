# 仓库安全规则

## 交付边界

本仓库包含商户自身业务和对外接口契约，不存放提供方的管理操作手册、内部数据库设计、私有配置位置、本机运维记录或生产调查材料。测试使用合成数据，真实凭据不进入测试夹具。

Git 忽略、Docker 忽略和安全扫描互相补充，任何一项都不是绝对安全证明。站点转发安全与供应商专属协议重构属于另行审查的范围。

## 本地门禁

预先安装 Gitleaks 8.30.1，并确保 `gitleaks` 在 PATH 中。应用不会在提交时自动安装扫描器。

```powershell
git config --local core.hooksPath .githooks
npm run test:security
npm run check:security
```

- 提交前读取 **Git 暂存区**，不是同路径的工作区文件；未暂存的修改不能掩盖已暂存内容。
- 推送前和默认安全检查覆盖本地可达历史、reflog 及当前暂存区；拒绝浅克隆的不完整历史结论。
- 路径检查拒绝凭据、环境文件、运行数据、抓包、备份、子模块和符号链接；唯一允许的环境模板中，密钥、密码和令牌字段必须留空。
- 文档检查阻止本机绝对路径和提供方管理接口重新进入交付文档；不代替对实现原理的人工审查。
- Gitleaks 使用仓库配置与默认规则，补充服务接入密钥规则；不忽略整份测试目录，也不接受行内跳过标记或个人忽略文件。
- 发现问题只输出文件、行号、规则及已脱敏的扫描结果；禁止记录或上传原值。
- 扫描器、Git 或读取失败时停止操作，不把失败当成无泄露。

默认命令扫描已提交及已暂存内容。准备提交前应先暂存本次文件；未跟踪或未暂存内容不在 Git 检查的完整性声明内。

## 自动检查

GitHub Actions 对 push、pull request 和手动运行执行安全检查与回归测试。固定第三方 Action 提交，固定扫描器版本并校验下载 SHA-256；不使用商户运行凭据。

本地钩子可以被有权限的开发者绕过，因此建议在仓库设置中将 `Repository security` 设为必需检查。本仓库文件不会自动修改分支保护或 GitHub 秘密扫描开关。

## 构建与备份

Docker 上下文从“全部拒绝”开始，只放行构建必需的清单、源码和静态资源类型。本机预览、数据、日志、测试、备份和 Git 对象不参与构建。增加输入应与安全测试一起审查。

备份只能保存到仓库外的受保护位置，不能为了绕过扫描修改文件后缀或增加宽泛忽略规则。不要删除仍在使用的密钥、用户数据或运行目录。

## 历史清理

删除当前文件不会移除旧提交中的内容。历史重写应先获得授权并保留受保护恢复副本，再验证本地对象、远端引用、其他克隆和托管侧缓存。

本地清理不自动改变远端。未经明确授权不强推；获准更新时核对远端预期提交并使用明确租约，避免覆盖其他人的新提交。重写后应重新克隆，不要把旧分支合并回来。若确认真实凭据泄露，还需要撤销或轮换凭据，不能只改 Git。
