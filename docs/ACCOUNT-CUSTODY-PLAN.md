# 自有账号托管与交付：商户侧下一轮计划

日期：2026-11-01。状态：**六阶段本地实现与隔离验收已完成；真实供应商与上线验收待授权**。本文只规定本站职责、直接提供方所需的公开行为和验收，不包含提供方内部实现或管理操作。

当前接口以 [接口契约](API-CONTRACT.md) 和实际代码为准。本计划不是第二份 wire 合同。名额入口已移除，真实托管任务、来源隔离和具体交付已在本地实现；只验证隔离数据库迁移与受控提供方，不包含真实账号登录或生产迁移。

## 1. 本轮目标

有管理权限的本站商户 C 能授权添加自己的 Code 账号，经过直接提供方逐级托管；账号只进入 C 的可交付库存。C 给本站客户分配该账号，客户沿「C → B → A → 最终提供方」使用，不跳级、不自动换号、不重放请求。

同时收敛上一批的名额业务：不要求上级逐级预分配托管名额，不要求先采购账号库存或充值，不设置独立的必填托管到期。实际托管数量可以统计，但不是要分配的预算。

仍保留人员与接口权限、账号来源、真实占用、客户合同期限、上级供给的父期限、受控运行环境、幂等回执及服务端技术保护。取消名额不代表所有现存只读密钥自动获得写权限，也不代表无限硬件容量。

## 2. 顺序、改动与验收

| 阶段 | 商户侧工作 | 验收要求 |
| --- | --- | --- |
| 1. 收敛多余策略 | 删除名额字段、预算预留/扣减、独立策略表单及无调用方的入口；将确有需要的权限和环境信息放回账号接入职责 | 不需要名额配置即可进入后续接入流程；没有大整数伪装无限；旧账号业务不受影响 |
| 2. 来源与数据模型 | 持久化本地来源、直接上游账号/操作/占用 ID 及各自版本；区分本站自有、上级供给和下级中转 | 密钥轮换不改变来源；不能凭邮箱或展示名称合并；中转记录不成为本站可售库存 |
| 3. 授权接入 | 增加发起、提交、查询、取消和核对流程；在发送前保存稳定非秘密意图与上游操作映射 | 不保存供应商 token、授权码或完整回调；响应丢失能查原任务，不另建请求伪装重试 |
| 4. 库存与交付 | 将确认就绪的自有账号并入库存；传递并映射具体占用及修订号；更新客户、批次、设备和运行调用方 | 一个客户可持多个具体账号；必须实际使用所选账号；不以分组或展示编号代替占用 |
| 5. 生命周期与恢复 | 重新授权、暂停、收回客户使用权、退出托管和操作恢复；分别展示授权、交付及运行状态 | 未确认不显示成功，不释放未知占用；迟到回执不复活撤销；断线与撤销向上传递 |
| 6. 全链与发布准备 | 真实提供方实现 + 三个独立 Merchant 的 HTTP/浏览器、数据迁移与恢复回归；协调实际消费方版本 | 同时通过自带账号闭环和原有上级供给业务；完整验收前不对外开放加号 |

阶段 1 只是收敛，不是本轮最终交付。阶段 3 授权成功也不代表阶段 4 已可交付或阶段 5 已可安全退出。

## 3. 必须坚持的具体语义

### 不把托管当成购入库存

本站自带账号来源仍归本站；下级自带账号经过本站只是中转，不自动授予本站自用或再分配给其他分支的权利。直接提供方提供的可用事实与本地来源映射一起决定对象归属，不接受浏览器任意 owner 字段。

上级没有分配现成账号库存时，只要接入权限与有效环境具备，本站仍应能添加自己的账号。实际供给不足、授权未完成和提供方不可用必须分别展示。

### 无独立托管期限不等于所有空日期都永久有效

自有账号归属不按名额或任意日期到期；客户使用期限独立设置。上级供给账号仍不能超过实际父期限。旧记录缺失/无效期限保持待核对，不猜测为不限期，不填写虚构远期日期。

现有库存分类、筛选、交付和续期代码依赖有限期限，必须在明确来源类型后一起调整，不能只隐藏表单字段。

### 每层是有责任的接入方，不是无条件透传

每层验证直接调用方，查找本层拥有的映射，使用自己的上游密钥请求直接提供方。客户、资源、具体占用、授权、设备、操作及修订号分别映射；不得把本地版本直接转发成上游版本。

中间层只保存非秘密操作意图与事实。供应商 access/refresh token 由实际托管方保存和刷新；短暂转交的敏感回调不进入普通日志、审计正文、浏览器持久化存储或本地任务队列。

沿用相邻提供方受信任的代理模型，不宣称中间运营者在技术上无法读取经过进程的数据。

### 结果未知必须可恢复

首次请求发送前就有稳定操作标识，丢响应后仍能查询。授权码是否已经被使用无法确定时，显示待核对/重新授权，不自动重复兑换。账号未被确认就绪前，不显示为可分配。

暂停来源账号、收回客户使用权和退出托管是不同操作。退出确认前保留映射与历史；本地停用不能宣称已撤销供应商侧授权。换密钥不改变来源，更换直接提供方或跨来源转让不在本轮范围。

## 4. 本仓库改动范围

- `src/custody.js`、`src/custody-schema.sql`、`public/owned-accounts.js` 及已有接入处：收敛名额业务；有效的映射/核对职责迁入真正的账号接入实现，失去调用方的代码同批删除。
- `src/access.js`、`src/upstream.js`、`src/server.js`：权限、允许字段、直接提供方交互、相邻 ID/版本映射和管理入口。
- `src/store.js`、各责任 schema、恢复调度：持久化非秘密意图和事实；迁移保留用户、财务、授权、设备及历史。
- `src/inventory.js`、客户、批次、订单和设备调用方：具体账号交付、来源与期限语义；自带账号不强制绑定购买或付款流程。
- `public/api.js`、账号/库存/接入页面：正确回执校验、待核对状态和闭环操作，不把登录成功当作可交付。
- 服务端、浏览器和多跳回归：保留真实边界测试，替换只验证名额规则的失效测试。

不新增只做转发的便利函数、旧名字别名或两套登录/运行实现。新旧接口不双轨；实现时同步当前合同、所有实际调用方和测试。

## 6. 数据与发布边界

先核对旧策略数据，保留受保护备份/归档，不因去掉名额就清库或删除运行目录。现有商户停用、密钥撤销、人员权限不能随着删策略自动放开；没有名额记录也不能被推断成禁止接入。

中间批次只做隔离验证，所有实际参与方协调切换后再放行。迁移和回退必须保留新增资产、来源映射和原始操作回执，不能让旧服务将新托管账号错误地作为公共库存处理。

完整自有账号主流程已在本地实现；测试记录与真实现场验收必须分开。本计划不授权真实账号登录、生产迁移、支付、发布或部署。
