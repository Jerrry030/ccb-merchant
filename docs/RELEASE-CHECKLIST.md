# 商户发布检查清单

本清单只覆盖本站，不包括提供方管理、数据库或运维。勾选必须依据本次实际证据，不能沿用历史报告中的成功结论。

## 仓库与构建

- [ ] `npm run test:security` 和 `npm run check:security` 通过；缺少扫描器必须失败。
- [ ] 扫描完整 Git 历史，而不只是最新文件；浅克隆不能作为完整历史证明。
- [ ] Git 中不含环境配置、凭据、运行目录、抓包、备份或内部运维记录。
- [ ] Docker 只接收 `.dockerignore` 白名单输入；增加目录或类型前检查其必要性。
- [ ] 发布使用已审查提交，不上传整个本机工作目录。

## 配置与持久化

- [ ] `DATA_DIR` 独立可写、位于静态目录之外，访问权限限于运行账号。
- [ ] 数据库、加密密钥和运行身份数据成套备份；在隔离目录验证恢复。
- [ ] `PUBLIC_ORIGIN`、HTTPS、Host/Origin 策略与实际部署一致。
- [ ] 仅使用本站获发的上游接入密钥；不向浏览器或下游交付该密钥。
- [ ] 私网或 HTTP 接入已明确批准；不使用重定向、通配目标或删除绑定记录绕过验证。

## 功能验证

- [ ] `npm test` 通过；浏览器环境准备完成后运行 `npm run test:browser`。
- [ ] 使用获授权的真实资源验证连接、流式响应、断线、期限和撤权。
- [ ] 邮件配置、测试发送、真实到达、验证与找回密码分别验证。
- [ ] 支付配置、签名通知、查单、重复通知、未知结果和交付分别验证。
- [ ] 真实收款前确认渠道资格、币种和交易规则；浏览器回跳不作为收款证据。
- [ ] 部署配置已使用 `RUNTIME_HEADER_TIMEOUT_MS`；不再保留旧的 `RUNTIME_TIMEOUT_MS`。
- [ ] 反向代理将 `/bridge/v1/*` 排除出响应压缩；接受 gzip 时，响应结束前仍可收到 SSE 进度。静态资源仍可压缩。
- [ ] 反向代理及时刷新 SSE 并传递取消，不设置负值 `flush_interval`。
- [ ] 验证持续流和响应头后的慢正文能超过响应头等待期限，等待响应头超时仍会取消，客户端断开不遗留请求且不重放。
- [ ] 控制接口完整响应超时、授权撤销及并发限制仍然生效。

不要通过删除用户数据或运行目录修复未知订单、接入身份冲突或恢复问题。不要把编译、离线测试、联调和运营验收合并成同一结论。
