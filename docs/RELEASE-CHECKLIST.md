# 商户发布检查清单

[文档索引](README.md) · [开发与测试](DEVELOPMENT.md) · [升级、恢复与排障](OPERATIONS.md)

本清单只覆盖本站，不包括提供方的内部管理、数据库或运维。勾选必须依据本次实际证据，不能沿用历史报告中的成功结论。未执行、失败、不适用和通过分开记录；不适用必须写理由。

## 版本与范围

- [ ] 固定本次源码提交、构建产物/镜像身份、Node 版本和配置来源；不能只用包版本识别部署。
- [ ] 明确本次改变的业务、接口、参数、持久化文件及数据库迁移。
- [ ] 明确提供方和实际客户端版本/能力的已验证组合，不把“最新版”当作兼容结论。
- [ ] 文档索引、命令、配置表和示例与实际实现一致；没有承诺未实现能力。
- [ ] Node 版本文件、npm 锁文件和 Caddy 工具清单一致；工具升级已重新准备并回归。
- [ ] 核对对应提交所有必需 CI 作业的实际结果；工作流配置或本地通过不代替 GitHub 运行结果。

## 仓库与构建

- [ ] `npm run test:security` 和 `npm run check:security` 通过；缺少扫描器必须失败。
- [ ] 扫描完整 Git 历史，而不只是最新文件；浅克隆不能作为完整历史证明。
- [ ] 待发布文件已纳入实际扫描范围；未暂存/未跟踪内容不能借历史检查宣称安全。
- [ ] Git 中不含真实环境配置、凭据、运行数据、抓包、备份或私有运维记录。
- [ ] Docker 只接收 `.dockerignore` 白名单输入；增加目录或类型时同步安全测试和[架构说明](ARCHITECTURE.md)。
- [ ] 构建使用已审查源码；未将整个本机工作目录作为部署包上传。记录实际镜像，而不只记录浮动基础标签。

## 配置与持久化

- [ ] `DATA_DIR` 独立可写、位于静态目录之外，访问权限限于运行账号及获授权维护人员。
- [ ] 确认实际数据目录/卷及 Compose 项目身份；不因挂错空卷而重新初始化。
- [ ] 数据库、加密密钥和运行身份数据成套备份，环境托管的凭据另行保护；在隔离副本验证恢复。
- [ ] 记录 schema 迁移和回退条件，保留匹配的旧程序/镜像与备份；恢复副本不连接真实外部服务。
- [ ] `PUBLIC_ORIGIN`、HTTPS、Host/Origin 策略与实际部署一致；初始化没有放宽直连回环限制。
- [ ] 仅使用本站获发的上游接入密钥；不向浏览器或下游交付该密钥。
- [ ] 私网或 HTTP 接入已明确批准，不使用重定向、通配目标或删除绑定记录绕过验证。
- [ ] 核对 Compose 实际传入参数；只修改 `.env` 不能证明所有配置已进入容器。

## 功能与运行验证

- [ ] `npm test` 通过；浏览器环境准备完成后运行 `npm run test:browser`。
- [ ] 代理变更或部署需验证流式行为时运行 `npm run test:proxy`；记录实际 Caddy 版本。
- [ ] `/api/public` 可读取、初始化状态正确；它不替代管理员登录、上游或支付健康检查。
- [ ] 验证管理员权限、客户数据隔离、临时密码改密和设备操作；未授权角色不能依靠直接请求绕过界面限制。
- [ ] 使用获授权的真实资源验证连接、流式响应、断线、期限和撤权，另行记录实际客户端版本。
- [ ] 邮件配置、测试发送、真实到达、验证与找回密码分别验证。
- [ ] 支付配置、签名通知、查单、重复通知、未知结果和交付分别验证。
- [ ] 真实收款前确认渠道资格、币种和交易规则；浏览器回跳不作为收款证据。
- [ ] 部署配置使用 `RUNTIME_HEADER_TIMEOUT_MS`，不保留不再生效的 `RUNTIME_TIMEOUT_MS`。
- [ ] 反向代理将 `/bridge/v1/*` 排除出响应压缩；接受 gzip 时响应结束前仍可收到 SSE 进度，静态资源仍可压缩。
- [ ] 反向代理及时刷新 SSE 并传递取消，不设置负值 `flush_interval`。
- [ ] 持续流和响应头后的慢正文可超过响应头等待期限；等待头部超时仍会取消，客户端断开不遗留请求且不重放。
- [ ] 控制接口完整响应超时、授权撤销及并发限制仍生效；未知订单和批次使用原意图核对。

## 验证记录模板

清单本身不是通过记录。每次发布使用以下字段记录实际结果；公开版本只保留脱敏摘要，详细日志、真实交易信息和备份位置留在受保护记录中。

| 字段 | 本次填写 |
| --- | --- |
| 日期、操作者与变更范围 | 待填写 |
| 源码提交、工作区是否含额外变更 | 待填写 |
| 构建产物/镜像身份 | 待填写；仅本地源码检查时注明未构建 |
| Node / npm / Gitleaks / Playwright / 浏览器 / Caddy | 记录实际使用项及版本，其余写未使用或未确认 |
| 直接提供方与实际客户端版本 | 未验证时明确填写未验证，不记录密钥或私有配置 |
| 命令与场景 | 填写实际执行的命令、输入类别与测试范围 |
| 编译/构建 | 未执行 / 通过 / 失败 / 不适用及理由 |
| 隔离测试 / 浏览器 / 代理 | 分项填写，不能用任一工作流绿灯替代其余检查 |
| 真实提供方 / 邮件 / 支付 | 分项填写授权范围、结果和未覆盖项 |
| 备份恢复 / 回退条件 | 填写验证结论，敏感位置仅留在受保护记录 |
| 提交 / 推送 / 部署 / 已安装客户端 / 用户确认 | 五项分别记录，不能相互推断 |
| 剩余风险与是否放行 | 明确阻塞项、责任人与决定 |

不要通过删除用户数据或运行目录修复未知订单、接入身份冲突或恢复问题。不要把源码修改、编译、离线测试、真实联调、生产部署和运营验收合并成同一结论。

## 自有账号迭代发布门禁

- 协调所有实际直接提供方和商户一起切换，先用隔离环境核对来源映射和具体交付。
- 备份 SQLite、配置加密材料与 runtime_salt；恢复必须保留原 ID、来源及任务回执。新版 SQLite 标识为 6，旧程序不能直接打开，禁止只回退代码或清掉新资产。
- 现存服务密钥不自动增加 managed_accounts 权限；按需显式签发并保留轮换路径。
- 本地自动化通过不代表真实供应商登录或生产部署；使用单独授权的测试账号进行真实授权/刷新/运行验收。
