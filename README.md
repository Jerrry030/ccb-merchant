# CCB Merchant

独立部署的商户站，用于管理本站客户、账号交付、套餐、支付、设备和 API 接入，并将获授权的运行请求转发到直接提供方。

**Node.js 24.15+（仅 24.x） · SQLite · 原生浏览器 ES 模块**

## 主要能力

- **账号交付**：查看库存，按客户分配、续期或收回账号；批次保留逐项结果，未知结果单独核对。
- **客户与设备**：管理客户资料、登录安全和管理权限，协助设备确认、改名、账号选择及撤销连接。
- **销售与支付**：管理套餐、钱包、支付订单和交付；付款确认、交付完成与退款是不同状态。
- **API 接入**：管理本站 API 客户和独立密钥，只开放本站获授权能力的子集。
- **运行转发**：支持 Code 客户端的授权请求和流式响应，限制目标、体积和并发，传递断线取消；不自动重放运行请求。

商户只需要直接提供方的公开服务地址、本站专用接入密钥和获分配的资源，不需要提供方管理员凭据。提供方内部管理、数据库和私有运维资料不属于本仓库。

## 本地快速启动

需要 Node.js 24.15+（24.x）和 npm。已有部署不要重新复制配置，也不要换用空数据目录。

在仓库根目录执行以下 PowerShell 命令：

```powershell
node --version
npm ci
if (!(Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
npm start
```

1. 保持模板中的本地监听配置，浏览器打开 `http://localhost:8787`。
2. 首次启动会在 `DATA_DIR` 中生成 `setup.secret`。只在本机读取，在初始化页面输入令牌并创建管理员；使用后失效，不向他人发送，不提交到 Git。
3. 在「设置 → 上游连接」核对并保存直接提供方地址和本站密钥。也可以由部署环境同时设置 `UPSTREAM_URL`、`UPSTREAM_API_KEY`，此时页面只读。
4. 按「库存 → 分配客户 → 客户开始使用」完成交付。未配置或没有获授权资源时，不会产生可用的示例库存。

首次初始化要求服务进程的直连回环请求。容器或远程 HTTPS 部署不能照搬本地浏览器初始化步骤，见[部署与配置](docs/DEPLOYMENT.md)。

## 工作原理

```text
管理员 / 客户浏览器 ── 本站会话 ──┐
下级 API 客户服务端 ── 本站密钥 ──┼── CCB Merchant ── 本站上游密钥 ── 直接提供方
Code 客户端 ──────── 设备授权 ───┘        │
                                        ├── SQLite 与配套密钥
                                        └── 已配置的邮件 / 支付渠道
```

本站账户、设备授权和服务接入密钥不是同一种身份；各跳资源 ID 都需验证归属。客户期限不得超过本站获授权期限，不向浏览器或下游交付本站上游密钥。实现职责和持久化边界见[架构](docs/ARCHITECTURE.md)。

## 支持范围与安全边界

- 当前运行接入只开放 Code；有转发路由不等于支持 Desktop 或其他客户端界面。提供方和客户端版本必须按[接口契约](docs/API-CONTRACT.md)另行验证，不能因项目同名或安装了最新版就视为兼容。
- 付款以服务端验签和查单为依据，浏览器回跳不是收款证明；原路退款、换号补偿和主动更新上游额度不在当前承诺内。
- 私网或 HTTP 提供方必须明确批准；页面配置与环境配置的批准方式见[部署与配置](docs/DEPLOYMENT.md)。
- 数据库、配套密钥和运行身份数据必须成套保护。不要通过删除数据、重新初始化或更换请求标识处理未知结果。
- 编译、隔离测试、浏览器测试、真实联调和用户验收分开记录。仓库提供独立安全检查以及服务端、浏览器、代理分层 CI；是否通过以对应提交的实际运行结果为准，不自动发布或部署。

## 开发与维护

浏览器端直接加载 ES 模块，没有前端构建步骤。安装依赖后可执行 `npm test`；其他测试的工具准备、适用范围和命令集中在[开发与测试](docs/DEVELOPMENT.md)。

| 路径 | 职责 |
| --- | --- |
| `src/` | HTTP 服务、商户业务、授权转发、SQLite 与后台核对 |
| `public/` | 页面、样式、字体及前后端共享规则 |
| `tests/` | 服务端、浏览器、安全和反向代理回归 |
| `scripts/`、`.githooks/` | 仓库安全检查与本地 Git 门禁 |
| `docs/` | 操作指南、架构、契约和发布规范 |

发布前执行[发布检查清单](docs/RELEASE-CHECKLIST.md)；协作遵守 [AGENTS.md](AGENTS.md) 和[仓库安全规则](docs/SECURITY.md)。
