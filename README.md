# CCB Merchant

独立部署的商户站：管理本站客户、账号交付、套餐、支付与设备，并将获授权的运行请求转发到直接提供方。运行环境为 Node 24.15+（24.x）和 SQLite。

## 仓库边界

- 商户只依赖提供方公开接口、本站接入密钥和本站获分配的资源。
- 提供方的管理员操作、内部数据模型、私有部署配置和故障调查记录不属于本仓库。
- 本仓库的客户、订单、财务、设备与 API 接入管理是商户自己的职责。
- 对接规则见 [公开接口契约](docs/API-CONTRACT.md)，人工交付见 [账号交付](docs/ACCOUNT-ALLOCATION.md)。
- 文档整理不等于运行协议已重构；厂商专属运行时处理的迁移不在本次改动范围。

## 本地启动

在仓库根目录执行：

```powershell
npm ci
Copy-Item .env.example .env
npm start
```

默认仅监听本机 8787 端口。浏览器打开 `.env.example` 中的 `PUBLIC_ORIGIN`。首次启动生成 `data/setup.secret`；在商户初始化页面输入该令牌并创建本站管理员。令牌只能本机读取，使用后失效，不发送给他人、不提交到 Git。

修改 `DATA_DIR` 时，令牌和持久化文件也位于所选目录。不要删除运行目录来处理连接、支付或交付错误。

## 连接直接提供方

由提供方向本站交付服务地址及本站专用接入密钥。无需登录提供方管理后台，也不需要获得其管理员凭据。

- `UPSTREAM_URL` 与 `UPSTREAM_API_KEY` 同时配置：由环境管理，页面只读。
- 两项同时留空：由本站管理员在「站点设置 → 上游接入」验证并保存。
- 保存配置前核对提供方身份；已有数据不能通过更换身份或删除绑定记录强行迁移。
- 公网连接使用 HTTPS。私网或 HTTP 地址需通过 `UPSTREAM_ALLOWED_ORIGINS` 显式允许。
- 接入失败、结果未知和未配置必须保持可见，不能显示成成功或虚构库存。

## 销售与交付

当前主流程为「账号库存 → 分配客户 → 客户开始使用」。客户期限不得超过本站获授权期限。设备页支持改名、选择账号、清空选择和撤销连接；管理员可从客户管理处理客户设备。换机前先解除旧设备的账号选择或撤销连接，不自动抢占。

套餐、钱包和在线支付能力独立保留。服务端验签及查单确认才是支付依据，浏览器回跳不代表收款。配置页面支持的渠道及币种以当前接口返回为准；保存配置或通过离线测试不等于渠道真实收款验收。

本站可管理自己的 API 客户和接入密钥。该密钥与本站上游密钥独立，不向下游交付上游密钥；所有资源仍受本站获授权范围约束。

## 部署与数据保护

- `.env.example` 是配置模板，真实配置只留在部署环境。
- 远程访问必须显式配置 `ALLOW_REMOTE`、`PUBLIC_ORIGIN` 和 HTTPS。
- `DATA_DIR` 必须位于静态资源目录之外，并限制为运行账号可访问。
- 数据库、加密密钥和运行身份数据需要成套受保护备份，不能只备份数据库。
- HTTPS 反向代理示例见 `Caddyfile.example`。示例将 `/bridge/v1/*` 排除出响应压缩，避免 Caddy 2.6.2 的 gzip 缓冲流式事件，同时保留静态资源压缩。Caddy 自动及时刷新 SSE；不要设置负值 `flush_interval`，否则客户端断开后提供方请求可能继续运行。
- `RUNTIME_HEADER_TIMEOUT_MS` 默认 600000，仅限制模型/透传请求等待上游响应头的时间；收到成功响应头后不再按总时长截断 SSE 或非流式正文。升级时将部署配置中的 `RUNTIME_TIMEOUT_MS` 改为该名称，旧配置项不再使用。
- 控制接口仍由 `UPSTREAM_TIMEOUT_MS` 限制完整响应时间。客户端断开或授权撤销会取消进行中的请求，本站不会自动重放请求。
- Docker 构建采用输入白名单，不发送本机预览、凭据、日志、备份和测试数据。

部署前逐项执行 [发布检查清单](docs/RELEASE-CHECKLIST.md)。

## 开发与验证

```powershell
npm test
npm run test:security
npm run check:security
npm run test:browser
npm run test:proxy
```

`test:security` 和 `check:security` 需要 PATH 中已有 Gitleaks 8.30.1；不会自动下载或跳过缺失的扫描器。浏览器环境见 [浏览器测试](tests/browser/README.md)。

`test:proxy` 使用实际 Caddy 验证示例配置在 identity/gzip/CLI 压缩列表下都能在响应结束前收到 SSE 进度，并检查取消传递和静态资源 gzip；需要 PATH 中的 Caddy，或通过 `CADDY_BIN` 指定可执行文件。测试仅启动隔离的本机临时端口，不调用真实提供方。

本地启用 Git 门禁：

```powershell
git config --local core.hooksPath .githooks
```

提交前检查暂存区，推送前检查可达历史与暂存区；CI 对完整检出的历史执行相同检查。扫描输出不回显秘密。详见 [仓库安全规则](docs/SECURITY.md)。

编译、隔离测试、浏览器测试、真实提供方验证和用户验收分别记录；任何一种都不能替代其余验证。
